# SEO.md — The Trading Narrative

Rules that every new page and essay must follow. Written for future maintainers
(and future agents). Last updated: Phase 42.

## Access model (server-enforced, no cloaking)

- **Archive/listing pages are fully public**: titles, dates, tags, excerpts. No login needed.
- **Metered anonymous reading**: a logged-out visitor may read **3 complete free-tier essays**.
  - Tracked via first-party cookie `fv_slugs` (90-day expiry) **plus** a server-side record
    keyed to `sha256(IP + User-Agent)` in the `meter_reads` collection (union of both;
    re-reading a counted essay never consumes quota).
  - On the 4th essay: server returns only the preview (~250 words or first 2 blocks,
    whichever is shorter) with `lock_reason: "meter"`.
- **Hard-locked, never metered** for non-premium: `tier: premium` essays, anything tagged
  `lounge`, and the 3 most recent premium editions. These always render preview-only.
- **Signed-in free users**: read all free-tier essays in full; premium essays show a
  3-paragraph preview. Early supporters (first 50 accounts) additionally unlock the 5
  earliest published essays.
- **Premium users** bypass everything.
- **NEVER user-agent sniff to unlock content for crawlers.** Googlebot receives exactly
  what an anonymous human receives. Paywalls are signalled via structured data instead.

## Structured data

Every essay page emits JSON-LD (`NewsArticle`) with:
- `isAccessibleForFree: true` for open (free-tier) essays — `hasPart` omitted.
- `isAccessibleForFree: false` + `hasPart.cssSelector: ".paywalled-content"` for locked ones.
- The locked body region is wrapped in `.paywalled-content`; the free preview text sits
  **outside** it.
- Emitted in two places: client-side via Helmet on `/post/:slug`, and server-side in the
  crawler HTML at `/api/share/{slug}`.

## On-page rules

- Slugs are semantic and keyword-bearing (generated by `utils.slugify` from the title).
  Never hand-write hash-style slugs.
- One `<h1>` per page (the headline). Essay sub-sections use `## ` blocks which render as `<h2>`.
- `<title>` ≤ 60 chars, `<meta name="description">` ≤ 155 chars — both come from the
  excerpt via the shared `<Seo>` component (`title · The Trading Narrative`).
- `<link rel="canonical">` self-referencing on every page (handled by `<Seo>`).
- Open Graph + Twitter `summary_large_image` tags on every page (handled by `<Seo>`).
- Every image needs descriptive `alt` text. For charts, describe what the chart shows.

## Site architecture

- Topic hubs at `/topics/{category}` (tech-business, finance, delivery, lifestyle), each
  with 200–400 words of **original** intro copy (in `TopicPage.js`) + the chronological
  essay list + a link to `/archive`. These target head terms — keep intros original.
- Every essay links to its topic hub (category badge) and to 3 related essays.
- `/api/sitemap.xml` auto-generates: home, archive, briefings, pricing, about, all topic
  hubs, all category pages, all published essays with `lastmod`. Referenced in `robots.txt`.
- `robots.txt` allows essay/archive/hub routes; disallows `/admin`, `/account`, `/auth`,
  `/payment/`, `/api/` (with explicit Allow for sitemap, feed, and share endpoints).
- RSS at `/api/feed.xml`: full text for free essays, preview + link for locked ones.
  Discovery `<link rel="alternate">` is in `public/index.html`.

## Copy style

- No em/en dashes mid-sentence — use commas, colons, or middots. Numeric ranges keep the
  en dash (83–84). Leading attribution dashes ("— The Trading Narrative") are fine.
- Email subjects use `·` as the title separator, not `—`.

## Verify after content/access changes

1. `curl -s https://<domain>/api/posts/<slug>` with no cookies: preview present, locked
   body absent, `lock_reason` correct.
2. `curl -s https://<domain>/api/share/<slug>`: JSON-LD present and valid (run through
   Google's Rich Results Test).
3. Meter: 3 anon reads grant full text, the 4th returns the preview; re-reads don't
   consume quota; premium/lounge essays never unlock via the meter.
4. A premium session sees the full body and no meter banner.

## Keyword targeting (Phase 45)

Head terms the site is tuned for and where each one lands:

| Keyword               | Primary landing surface                                   |
|-----------------------|-----------------------------------------------------------|
| trading / narrative   | Homepage (`/`) title, WebSite JSON-LD `alternateName`      |
| freight               | Freight essay, `/topics/tech-business` hub, home meta      |
| business and finance  | `/topics/finance` hub ("Business & Finance..."), archive   |
| weekly briefing       | `/briefings` page title + description                      |
| newsletter            | Homepage + `/briefings` titles, Organization JSON-LD       |
| shipping industry     | Shipping essay, home meta keywords                         |

Implementation notes:

- `public/index.html` carries the crawler-first title
  "The Trading Narrative — Trading, Freight & Business and Finance Newsletter",
  a keyword-rich meta description, and a `keywords` meta tag.
- `components/Seo.js` sets the same defaults for every page that does not override
  them, and accepts `keywords` and `jsonLd` props for page-level tuning.
- Homepage emits `WebSite` + `Organization` JSON-LD (`@graph`), including
  `alternateName` ("Trading Narrative", "The Trading Narrative Newsletter") and
  `knowsAbout` topics, which helps Google map brand + head-term queries to the domain.
- Keep titles under ~70 chars with the keyword phrase before the separator.
- Ranking for broad heads (e.g. bare "trading") depends on links + time; the on-page
  signals here make the site eligible, Search Console tracks the rest.

### Meta tag ownership convention (react-helmet-async v3)

- Static fallback meta tags in `public/index.html` are marked `data-rh="true"`.
- Helmet v3 renders its tags WITHOUT `data-rh`; the `Seo` component removes all
  `head meta[data-rh]` on mount so a rendered page has exactly ONE description /
  og:title / keywords tag (page-specific values win).
- No-JS crawlers still see the static keyword-rich fallbacks in the raw HTML.
- If you add new static meta tags to index.html that React should replace, mark
  them `data-rh="true"`; leave permanent ones (og:site_name, theme-color) unmarked.
